# AGENTS.md

Единственный источник «состояния проекта»: при смене архитектуры, порядка проверки или ограничений
править сначала его, потом `README.md`. Значения (константы, цвета, размеры, количества) здесь не
дублируются — они живут в коде; здесь только решения, причины и грабли.

## Как работать с задачами

Это MVP. Договорённость с владельцем репозитория:

- Простая задача — простое решение, без наращивания объёма; задачу самовольно не расширять.
- Проверки соразмерны правке: `lint` / `check-types` / `build` / headless-браузер — только когда
  реально нужны (перед коммитом либо когда правка может их сломать). Правил данные или `AGENTS.md` —
  перепроверять нечего. Владелец проверит сам и скажет.
- Коммит — только по прямой просьбе владельца. Его правки в рабочем дереве не откатывать.
- Правило линтера мешает — спросить владельца, можно ли его отключить; отключённое фиксируется в
  `.eslintrc.cjs`.

## Что это за проект

Учебная визуализация графа: React 19 + TypeScript + Vite; физика и DOM — на d3 (`d3-force`,
`d3-selection`, `d3-drag`, `d3-zoom`, `d3-scale-chromatic`), формы — на `react-hook-form`. Узлы —
научные работы (`node`) и цитирующие их патенты (`subNode`). Данные — TS-модуль `src/data/graph.ts`,
запроса к серверу нет, загрузка эмулируется `setTimeout`. Раскладка страницы и сцены — в CSS.
Исторически проект вырос из примера d3 про несвязный граф — сверяться с ним больше не нужно.

## Команды

- `npm run dev` — дев-сервер Vite (в проверках порт фиксировать: `-- --port 5199 --strictPort`).
- `npm run build` — `tsc -b` + сборка в `dist`; `npm run preview` — просмотр собранного (`--port 5198`).
- `npm run check-types` — только типы; `npm run lint` (= `lint-all`) — prettier + eslint с автофиксом.
- Пре-коммит `.git-hooks/pre-commit` запускает `npm run lint`; путь подключается `prepare` при `npm install`.

## Структура

- `src/App.tsx` — каркас страницы (хедер «Карта», `aside` слева, `main` с картой, пустой `footer`).
  Настройки и данные графа живут в его стейте: панель меняет, карта получает пропом. Здесь же
  `PanelView` — что открыто в левой панели (`settings` / `create` / `edit` с id): клик по ноде
  переключает панель с настроек на форму узла, правки данных идут только через `setData`.
- `src/App.css` — раскладка каркаса; `src/index.css` — `normalize.css` + системный шрифт.
- Компоненты экспортируются именованно, без default-экспорта.
- Комментарии не пересказывают код: нужен только «почему» — обоснование значения, следствие замера,
  ограничение. Остальное уже сказано именем или типом.
- `SettingsPanel/SettingsPanel.tsx` — форма настроек на `react-hook-form`: клоны нод, тоггл полного
  вида саб нод, чекбокс скрытия саб нод, range-поля физики, «Применить»/«Сбросить». Сабмит пишет в
  localStorage и отдаёт значения в `App`. Поля физики рисуются списком `NUMBER_FIELDS`, а не вручную;
  у каждого поля `title` с пояснением. В шапке — угловая кнопка «+» (`onStartCreate`,
  `type="button"`, чтобы не отправлять форму).
- `SettingsPanel/settingsPanel.ts` — логика панели без React: дефолты, опции клонов, `NUMBER_FIELDS`,
  ключ и чтение/запись localStorage. Дефолты физики импортируются из `forceGraph.ts`, чтобы панель и
  сцена не разошлись при подгонке по картинке. Разбор строки хранилища — чистая `parseGraphSettings`.
- `SettingsPanel/SettingsPanel.css` — вид панели (`settings-panel__*`): тоггл и чекбокс нарисованы
  подменами поверх настоящих input'ов; шапка `sticky`, угловая кнопка общая для «+» и «←».
- `SettingsPanel/nodeForm.ts` — правки данных графа без React и DOM: `updateNodeInData` (только
  `title`/`description`/`hasWarning`), `deleteNodeFromData` (узел плюс все его связи),
  `createNodeInData` (id `custom-N` и связи с выбранными соседями), `neighborOptions`,
  `NODE_TYPE_OPTIONS`, `nodeCaption`. Возвращают новый `GraphData`, исходный не мутируют.
- `SettingsPanel/NodeForm.tsx` — дровер узла: правка выбранной ноды (`id`/`type` показываются, не
  правятся) и создание новой с тремя searchable-секторами соседей на `react-select` (`Controller`).
  Смена типа сбрасывает выбранных соседей (`changeType`) — допустимый набор меняется. Меню рендерится
  порталом в `body` (`menuPortalTarget`), иначе его срежет `overflow-y: auto` панели.
- `SettingsPanel/NodeForm.css` — текстовые поля, подпись узла, ошибка валидации, красная кнопка
  удаления (`node-form__*`).
- `ForceGraph/forceGraph.ts` — чистая логика без DOM: константы сцены, `prepareGraph`,
  `createSimulation`, `createLinkForce`, `asDrawnLinks`, `createTypeColors`, `tintToWhite`, типы
  `NodeRenderData`/`SeedPoint`/`GraphPhysics`. Поля `GraphPhysics` необязательные: силы читают их
  через `??`, отсутствие поля означает прежнюю константу, а не ноль.
- `ForceGraph/forceGraphUpdate.ts` — сведение CRUD-операций в план: `readGraphState` (состояние
  читается из симуляции и силы связей, отдельного «прежнего графа» нет), `diffNodes`,
  `planGraphUpdate`, `applyGraphUpdate`. Чистый модуль — весь разбор проверяется в Node.
- `ForceGraph/crud/graphNodesCRUD.ts` — CRUD узла: `nodeKey`, `nodeRenderData`,
  `isNodeRenderDataChanged`, `buildNode`, `seedPosition`. Чистый.
- `ForceGraph/crud/graphLinksCRUD.ts` — CRUD связи: направленный `linkKey`/`linkKeyOf`, `diffLinks`
  (добавление/оставление, отбрасывание связи с несуществующим концом и дубликата), `collectSeeds`,
  `buildLink`. Чистый.
- `ForceGraph/forceGraphCloud.ts` — геометрия узлов без DOM: кегли, паддинги, `truncateToWidth`,
  `createCloudLayouts(nodes, measure)`. Мерка приходит аргументом, поэтому проверяется в Node.
- `ForceGraph/forceGraphText.ts` — `createTextMeasurer()`: offscreen-канва, единственное место, где
  ширина строки берётся у браузера.
- `ForceGraph/layers/graphLayer.ts` — базовый svg-слой: `Map<ключ → запись>` и `sync(data, dirtyKeys)`
  с enter/update/exit; перерисовка дописывается только элементам из `dirtyKeys`. `create()` возвращает
  всю запись, а не только элемент, иначе подтип с доп. полями (`NodeEntry.parts`) терялся бы и
  перерисовка падала на `entry.parts.body`. Снятый элемент очищается от `__data__` (`forgetElement`).
- `ForceGraph/layers/graphLinkLayer.ts` — слой связей: по `<line>`, толщина `√force`,
  `drawPositions()` переносит координаты концов.
- `ForceGraph/layers/graphNodeLayer.ts` — слой узлов: группа с фиксированным составом детей и
  ссылками на них в записи слоя (обновление пишет атрибуты без поиска по DOM). Вид сворачивается в
  `renderKey`; совпал — группу не трогаем, раскладка и мерка текста не вызываются.
- `ForceGraph/forceGraphView.ts` — единственный модуль, создающий DOM-сцену: svg, панорама/зум, drag,
  tick-отрисовка слоёв, клик по узлу (`onNodeClick(id)`), `update(data)`, `setPhysics(physics)` и
  `destroy()`. Клик отличается от перетаскивания признаком из `createDrag` (`wasDragging`): d3-drag не
  глушит `click` после жеста, и без порога смещения (`DRAG_CLICK_SLOP`) любой сдвиг узла открывал бы
  форму. Значения физики лежат в одном объекте замыкания, который читают силы и drag: `setPhysics`
  переписывает его, отдаёт параметры силам и разогревает симуляцию — сцена не пересобирается.
- `ForceGraph/ForceGraph.tsx` — React-обёртка: эмуляция загрузки, клонирование графа по `nodeClones`
  (`useMemo`), монтирование svg; React владеет только контейнером. Сцена создаётся один раз на первых
  данных, дальше — `handle.update(data)` и `handle.setPhysics(physics)`. Разрушение — отдельный эффект
  без зависимостей: в cleanup эффекта создания его давать нельзя, иначе React пересобирал бы svg на
  смену любой зависимости. Колбэк клика уходит наружу через ref-обёртку, чтобы в сцену попала
  стабильная функция, читающая актуальный проп.
- `ForceGraph/ForceGraph.css` — фигура растягивается на `main`, svg заполняет фигуру, пропорции держит viewBox.
- `src/data/graph.ts` — данные одним типизированным модулем (`graphData`), без `fetch`. Файл
  сгенерированный и очень длинный, `max-lines` для `src/data` отключён оверрайдом в `.eslintrc.cjs`.
  Связи перепакованы искусственно (см. «Правила работы с графом»), id патентов идут с пропусками:
  удалённые патенты своих номеров не отдают, и по `patent-N` всё ещё видно, откуда узел родом.
- `src/types/graph.ts` — типы данных и уровня симуляции; `src/types/settings.ts` — `GraphSettings`
  (числовые поля не опциональные: панель обязана привезти значения, а `GraphPhysics` опциональный,
  чтобы вызывающий передал только то, что крутит).

## Конвенции кода

Зафиксированы `.prettierrc.mjs`, `.eslintrc.cjs` и текущим кодом — не менять по вкусу:

- Форматирование — за `.prettierrc.mjs` и пре-коммитом, стиль по вкусу не править.
- Комментарии, JSDoc и тексты интерфейса — по-русски; JSDoc на каждом экспорте (кратко, про «почему»).
- `import type` для типов (`verbatimModuleSyntax`); порядок импортов наводит
  `prettier-plugin-organize-imports`.
- Объявлять функции до использования: `@typescript-eslint/no-use-before-define` из airbnb — ошибка.
- Не мутировать параметры обработчиков (`no-param-reassign`): в drag-хендлерах предмет жеста берётся
  в локальную переменную (`const { subject } = event`).
- Лимиты длины файла/функции (значения — в `.eslintrc.cjs`): при упоре делить модуль по
  ответственности, а не ужимать код; для `src/data` лимит строк погашен оверрайдом.
- Логика отделена от отрисовки: физику, данные и раскладку облаков проверяем в Node (без DOM), svg
  собирается только в `forceGraphView.ts`.
- Типам d3 нужны явные дженерики: `selectAll<SVGLineElement, DrawnLink>('line')`,
  `drag<SVGGElement, GraphNode, GraphNode>()` (третий параметр — subject); итерация по узлам — через
  `each((datum, index) => …)` + `select(node.nodes()[index])`, селекционные данные в `each` не приходят.
- Неиспользуемый параметр/проп переименовывается с подчёркиванием (`settings: _settings`): иначе
  `noUnusedLocals` даёт TS6133, а правило ради пары мест отключать не стоит.

## Правила работы с графом

- Силы: `forceLink` + `forceManyBody` + `forceX`/`forceY`. Заряд масштабируется как площадь, дистанция
  связи короче растяжки — связанные узлы должны стоять плотнее тех, что просто отталкиваются. Это две
  независимые ручки: дистанция — плотность связок внутри кластера, заряд — простор между узлами;
  подгоняются по картинке. Позиционирующие силы линейны и не меняются — они принципиальны: у графа
  много несвязных компонент, и `forceCenter` разносит их за пределы сцены.
- `LINK_STRENGTH` задана явно и слабо (плоское значение для всех связей): формула d3
  (`1 / min(степеней концов)`) листовым связям отдавала полную силу 1. Замер: ослаблять связку ниже
  типичного для d3 не надо — связки расползаются, «желе» так не лечится. Заряд тоже не ручка «желе»:
  снижение `|CHARGE_STRENGTH|` и обрезка `distanceMax` сжимают сцену, тела начинают налезать
  (наезды 8 → 15…42), а прокат от жеста остаётся или растёт. Простор между облаками держится зарядом,
  поэтому его не трогаем.
- Главная ручка «желе» — разогрев drag'а (`DRAG_ALPHA_TARGET`): замер показал, что снижение вдвое
  (0.1 → 0.05) вдвое уменьшает прокат остальных узлов и остаточный сдвиг карты, тогда как ослабление
  связки даёт обратный эффект. Ниже 0.05 соседи за курсором уже не поспевают; демпфирование выше
  текущего тоже вредит — движение уходит в фазу остывания, раскладка садится в другое равновесие.
- `link.force` физика пока не читает: поле хранится на будущее, сейчас из него считается только
  толщина линии. Неиспользуемые поля исходных данных в проект не переносились.
- Данные — не буквальный граф цитирований, а его форма для раскладки: 100 работ исходные, патентов
  оставлено 112 из 236, часть связей переназначена. Лечились две болезни исходных данных: россыпь
  компонент из двух узлов (работа + патент) и «звёзды» (одна работа с десятком патентов). Правила
  перепаковки: компонента — либо сохранённая пара (11 штук), либо кластер 3–8 узлов (2–6 работ +
  1–6 патентов); патенты-связки держат по две-три работы, остальные висят листьями; там, где исходная
  компонента уже укладывалась в норму, ничего не переписывалось. Перепаковка разовая и живёт в
  истории — отдельного генератора в проекте нет.
- Кластеры заданы данными, а не физикой: если карта покажется разрозненной, сначала смотреть на форму
  данных, а не крутить `LAYOUT_SCALE`/`LINK_DISTANCE`. Плотность связок и простор между узлами — это
  подгонка по картинке, и в кластеры она узлы не собирает.
- Константы физики — источник дефолтов, но переопределяются из панели (`GraphPhysics`): в код значение
  переезжает только подтверждённым как новое постоянное и вместе с обоснованием замера. Правильные
  значения живут у константы, а не в localStorage: хранилище отдаёт старые настройки целиком, если
  поля не сошлись (`parseGraphSettings`).
- Цвет — по `type`, оттенки выдаются в порядке первого появления типа, легенда не нужна. Типов два:
  `node` — научные работы, `subNode` — цитирующие их патенты.
- Тела узлов — скруглённые прямоугольники центрами на координатах узла; группу двигает один
  `transform: translate(x,y)`, поэтому внутри всё считается от нуля. Заливка — светлый оттенок цвета
  типа (`tintToWhite`), а не прозрачная: связи под облаком не просвечивают, оттенок типа остаётся.
  `node` — «облако» по размеру текста, `subNode` — почти круг с яркой точкой. Кегли, паддинги,
  скругления и потолок ширины — в `forceGraphCloud.ts`.
- Текст мерит offscreen-канва той же гарнитурой (`FONT_FAMILY`), которой он рисуется: иначе
  `measureText` расходится с отрисовкой. Семейство задаётся и на группе узла — атрибут не наследуется
  в канву.
- Короткие подписи работ — русские и авторские, а не перевод исходных названий: полное название не
  теряется, оно в `description`. Так и оставляем.
- `type` — только два значения, третьего не будет: данные `subNode` не чистим, контент понадобится,
  когда иконка начнёт раскрываться.
- `hasWarning` — под красную точку в левом верхнем углу облака: слева резервируется колонка
  `WARNING_GUTTER`, текст сдвигается правее. Сейчас у всех узлов `false`.
- Узел несёт короткий `title` и необязательный `description`; в нативной подсказке (`<title>`) видно
  оба (`nodeTooltip`), на карте — обрезанные подписи.
- Панорама/зум — добавка к базовой раскладке; сетка фона удалена целиком. Узлы жест панорамы не
  перехватывают (d3-drag глушит всплытие).
- Клонирование нод (`nodeClones`) клонирует граф целиком, а не размер узлов: каждая копия получает id
  с префиксом `N-` и свои связи. Это ручка «посмотреть на много компонент»; множителя размера узлов в
  проекте не будет.
- Данных с сервера нет и не будет: состояние «Загрузка графа…» — чистая эмуляция. Если данные
  когда-нибудь вернутся в запрос, `resolveJsonModule` в `tsconfig` не включён — импорт JSON не
  «просто заработает».

### Инкрементальное обновление сцены

- Сравнение изменений — **по значениям**, а не по идентичности объекта: данные приезжают новым
  массивом и могли быть изменены на месте. Снимок сравниваемых полей (`nodeRenderData`) снимается с
  прежних узлов **до** сборки новых, иначе правка уже отразится в «прежнем» состоянии и станет
  невидимой.
- Неизменённый узел переиспользуется тем же объектом: на него держатся предмет drag'а, данные
  отрисованной группы и концы связей. Изменённый узел обязан стать **новым** объектом: правка полей
  прежнего обнулила бы следующее сравнение, и повторная правка того же узла перестала бы замечаться
  (регрессия проверяется в Node).
- Ключ связи направлен (`l:source>target`): `a→b` и `b→a` — разные связи, а переназначение конца —
  exit старой и enter новой, не правка. Сравнение связей идёт по исходным `GraphLinkInput`: в объекте
  связи `forceLink` уже подменила концы узлами и ключ прежней связи не восстановить.
- Связи при обновлении пересобираются новыми объектами: `forceLink.links()` заново разрешает строковые
  концы, так что переиспользование прежнего объекта ничего бы не сэкономило.
- Новый узел обязательно получает `x`/`y` **до** `simulation.nodes()`: d3 считает
  `isNaN(undefined) === false`, свою спираль не проставляет, и `NaN` расходится по всем силам. Точка
  высадки — вокруг центра масс известных соседей (`collectSeeds` + `seedPosition`); смещение ненулевое,
  потому что совпавшие координаты двух тел дают деление на ноль в силах.
- Порядок вызовов в `update()`: `simulation.nodes()` (проставляет `index`) → `linkForce.links()`
  (разрешает концы, пересчитывает `bias`) → `alpha(UPDATE_ALPHA).restart()`. Без `restart()` остывшая
  симуляция не сдвинется, даже если `alpha` поднят.
- Смена `type` узла меняет его цвет, а значит и вид его связей: они попадают в `changed.links`, хотя
  их данные не менялись.
- Слой не трогает существующий DOM-элемент, если его ключ не в `dirtyKeys`; если при этом и
  `renderKey` группы равен прежнему, раскладка облака и мерка текста не вызываются вовсе (страховка от
  перерисовки по чужой причине). Снятый элемент очищается от `__data__`: иначе он держит объект
  симуляции, а тот через концы связей — весь прежний граф.
- Дубликаты id схлопываются в первую запись, связь с отсутствующим концом отбрасывается на разборе:
  второй узел с тем же id попал бы в `simulation.nodes()` дважды (d3 падает на `index`), а такая связь
  надорвала бы `linkForce.links()`.

## Как проверять изменения

Перед коммитом обязательно: `npm run lint` и `npm run check-types` — оба должны дать exit 0. Вывод
`tsc` цветной, при разборе через grep его надо чистить: `| sed -e 's/\x1b\[[0-9;]*m//g'`.

Логика без браузера (быстро, ловит NaN, нерезолвленные связи, утечку мутаций):

1. Скрипт — **внутрь проекта** (из `/tmp` не резолвится `vite`), Vite в SSR-режиме:

   ```js
   const server = await createServer({ root: process.cwd(), server: { middlewareMode: true }, appType: 'custom' })
   const mod = await server.ssrLoadModule('/src/components/ForceGraph/forceGraph.ts')
   ```

2. Инварианты данных и симуляции: узлов/связей ровно столько, сколько в `graphData`; id уникальны,
   концы связей найдены; после `createSimulation` `link.source`/`link.target` — объекты; `prepareGraph`
   не портит `graphData`; `alpha()` доходит до `alphaMin` (сравнивать с допуском); нет нечисловых
   координат; `createTypeColors` даёт разным типам разные цвета.
3. «Желе» мерить жестом в Node: сначала довести симуляцию `tick`-ами до `alphaMin` (иначе в прокат
   попадёт раскладка, а не жест), потом двигать узел через `fx`/`fy` по 8 единиц за тик с
   `alphaTarget` как при drag. Считать прокат остальных узлов и остаточный сдвиг карты, нормировать на
   пройденный путь. Обязательно — геометрия покоя (просвет связанной пары, число наездов тел): от
   разогрева жеста равновесие не зависит, так что неизменная геометрия и есть контроль картинки.
4. Мерку текста подменять своей (`(text, size) => text.length * size * 0.55`). Проверить
   `truncateToWidth` (префикс с одним «…», влезает в потолок, короткую строку не трогает) и
   `createCloudLayouts` (запись на каждый узел, облака с описанием выше, левый край текста сдвинут на
   паддинг и на `WARNING_GUTTER` при `hasWarning`).
5. Инварианты обновления (`forceGraphUpdate` + `crud/*`): идентичные данные дают пустой план,
   неизменённый узел остаётся тем же объектом; правка заголовка отмечает только его; **две правки
   подряд одного узла** замечаются обе (ловит регрессию с мутированным «прежним» снимком); у нового
   узла координаты конечны и не нулевые; при удалении уходят и связи; дубликат id и связь в
   несуществующий узел отбрасываются на разборе. Отдельно — `createTypeColors` держит оттенок типа
   между обновлениями.
6. Удалить временный скрипт (он не должен попадать в коммит).

Проверка интерфейса — headless Chromium через Playwright (лежит в `devDependencies`):

- Запускать с `LD_LIBRARY_PATH=/tmp/pwlibs/usr/lib/x86_64-linux-gnu`: браузер из кеша
  (`~/.cache/ms-playwright`) собран под другой дистрибутив, libnspr4/libnss3/libasound2 надо
  распаковать из .deb без root (`apt-get download`, затем `dpkg-deb -x`).
- Дев на `http://127.0.0.1:5199/`, превью на `http://127.0.0.1:5198/`.
- Данные d3 читать из DOM: `el.__data__` на группе/линии.
- До жестов ждать покоя карты по координатам (две подряд спокойные выборки), а не по часам: alpha
  снаружи не видна, а снимок на разъезжающейся раскладке покажет ерунду.
- Узлы — группы, а не кружки: тело — `querySelector('rect')`, `getBBox()` возвращает координаты
  внутри группы (вокруг нуля), а не в пикселях сцены.
- Панораму и зум начинать внутри `svg`, но вне узлов (`elementFromPoint` +
  `closest('.force-graph__node')`), иначе жест перехватит drag узла.
- d3 оставляет `fx`/`fy` в `undefined`: сравнение с `null` строгим равенством даёт ложное
  «не сбросилось», надо `!= null`.
- Скриншот делать **до** жестов панорамы и зума.
- Чекбоксы панели настоящие, но спрятаны (`opacity: 0`, 1px): `locator.check()` на них падает
  («перехватывает pointer events»), кликать надо по `label`, клавиатуру проверять через
  `press('Space')` на самом `input`.

## Грабли, которые уже стоили времени

- Эмуляция загрузки на `setTimeout`: в `StrictMode` эффект выполняется дважды, но первый таймер
  снимается очисткой — данные приходят один раз, это норма.
- `npm run lint` запускает prettier по всему проекту: новый файл в корне будет переформатирован.
- Браузерная проверка работает только там, где есть кеш Playwright и распакованные `.deb`-библиотеки
  (`~/.cache/ms-playwright`, `/tmp/pwlibs`). В свежем окружении `chromium.launch()` падает на
  отсутствии исполняемого файла — это не поломка кода, и выдавать её за «проверено в браузере»
  нельзя: DOM-слой остаётся непроверенным, и это надо честно сказать в отчёте.
- `src/data/graph.ts` не стоит править вручную; prettier его сильно разворачивает.
- Исходные данные графа раздаются gzip-ом: `curl` без `--compressed` вернёт мусор.
- Мерку текста нельзя тянуть в чистые модули: `createTextMeasurer` трогает `document`, поэтому
  `createCloudLayouts` принимает мерку параметром. Иначе пробник в Node упадёт на его отсутствии.
- d3-drag не глушит `click` после отпускания мыши: drag и открытие формы по клику разводятся
  признаком движения из `createDrag`, а не `event.defaultPrevented` — тот на `click` не переносится.
- Ширина текста на канве и в svg совпадает не до последнего пикселя (разные хинтинги): подписи могут
  «съесть» единицу-другую паддинга, ловится тестом `getBBox()` в браузере.

## Состояние и следующий шаг

Каркас страницы, граф с физикой, панель настроек, инкрементальное обновление сцены и дровер узла — на
месте; детали правок в истории коммитов, актуальные значения в коде. Осталось:

- `showFullSubNodes` и `hideSubNodes` только доезжают до `ForceGraph`, сцену не меняют — ждут
  реализации в `forceGraphView`/раскладке.
- Раскрытие иконки `subNode` (её `title`/`description` для этого и сохранены), группировка узлов в
  «кучки», подписи и иконки в экранных пикселях, а не в единицах сцены (сейчас растут вместе с зумом).
- Обрезание подписей по ширине, без учёта числа строк: у описания всегда одна строка. Многострочное
  облако — точечная правка `createCloudLayout` (высота и центры строк считаются от блока строк).
- Доступность (клавиатура, не-нативные подсказки) — сознательно вне задачи.
